# Decision-Triggered Active Verification

DTAV is implemented as an explicit expected value of sample information (EVSI) approximation, not telemetry deltas renamed as a research algorithm. Unknown solar capacity P has a discrete prior at max(0,mu+sigma*z), z={-2,-1,0,1,2}, weights proportional exp(-z^2/2). Sigma grows with optional-report age (0.2+0.12*age W). Essential local monitoring continues regardless of report strategy.

Permissible supervisory bundles consume a in{0,1,4,6}W in priority order. Loss L(a,P)=(6-a)+12*max(0,a+0.5-P). The overload term penalises attempting service beyond uncertain supply; this dimensionless research objective does not replace hardware constraints. Prior best action argmin_a E[L]. Candidate observation outcomes reuse quadrature values; a Gaussian likelihood with measurement sigma0.15W updates posterior weights. Approximate EVSI=min_a E[L]-sum_y Pr(y)*min_a E[L|y]. Communication cost default0.08 loss units. Request only if posterior optimal actions differ across outcomes, EVSI>cost and minimum2s request spacing.60s health refresh bounds uncertainty. This five-point approximation is interpretable but its observation marginal and truncated-zero prior are coarse; evaluate sensitivity before stronger claims.

Sequence: estimate -> uncertainty -> enumerate bundles -> prior/posterior action comparison -> EVSI/cost -> choose solar-available measurement -> request over mock chain (over the hardware chain when real readings are valid) -> update report estimate -> recompute optional supervisory bundle -> deterministic power/safety policy -> local controller owns final actuation -> observe next state. Simulation forwards safety-limited service budgets after posterior reevaluation and records resulting load response. Hardware mode automatically requests useful fresh data when valid telemetry and MQTT are present; automatic service budgets require environment MICROGRID_DTAV_ARMED=1 after commissioning. Without arming the host does not actuate automatically. Service budgets affect optional loads only; critical service, source availability, current limits and battery reserve remain local. Hardware service budgets expire after30s without a renewed command and deterministic fallback resumes.

Baselines: continuous emits each1s simulation tick; periodic every30s; event when abs(P-last)>1W or age60s; DTAV as above. Identical plant profiles/seeds and local controller apply across all strategies. Report count is optional reports, not a model of total RF packet airtime; request/ACK packets and essential faults must be counted separately in any hardware study. Gateway and LoRa drop counters are observable; software hop validation does not implement a propagation/channel model or RF timing calibration.

Run scripts/experiment.py. CSV has seed,strategy,reports,requests,savings,MAE,unserved energy,detection and restoration delay. JSON has mean,std,n. Detection/restoration here mean optional-estimator crossing after known shade/recovery, not proven fault-identification latency or relay actuation time. All strategies use the same local safety policy, but different supervisory service budgets can change unserved energy. Report both communication and energy outcomes without assuming DTAV wins. The experiment is a baseline for research, not evidence of a novel algorithm or publication-ready superiority.

Extension plan: calibrate irradiance/current uncertainty, compare EVSI cost/measurement noise sweeps, record true packet bytes/airtime, inject timestamped packet loss/delay, pre-register allowed increase in unserved energy/critical service loss and false-isolation rate, then use paired confidence intervals across>=30 weather/noise seeds. Test negative results and high-communication regimes. Establish literature novelty separately; no unsupported novelty/performance claim is made.
