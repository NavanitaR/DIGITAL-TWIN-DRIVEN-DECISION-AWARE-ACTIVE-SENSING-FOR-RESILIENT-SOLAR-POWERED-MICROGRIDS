# Physical model and data semantics

Per-panel P_i=5W*irradiance(t)*shade_i*available_i; irradiance=clip(0.7+0.25sin(t/60),0,1). This is a transparent power approximation, not a single-diode PV I-V model; nominal6V is used only for synthetic cluster current. Hardware reports retain real bus/shunt values. Cluster power=sum member panel power. Isolation forces synthetic available_i=0. Shading scales production and cannot uniquely identify electrical fault cause.

Revision2 uses common-PV load priority: P_direct_input=P_load/0.88 when solar is selected; P_surplus=max(0,P_PV-P_direct_input); P_charge=min(0.90*P_surplus,V_bat*0.5A), subject to charge state and inhibit during transfer. Both functions can operate simultaneously. This is an idealized power-domain approximation of charger DPM, not an analog stability simulation.

Battery discharge power is P_discharge=P_load/0.85 when the battery source is selected, otherwise0. Signed pack current is I_bat=(P_discharge-P_charge)/V_bat, positive for discharge. SOC_next=clip(SOC-I_bat*dt/(3600*C_Ah),0,1). The synthetic battery voltage is V_bat=3.3+0.9*SOC before the integration step, and capacity defaults to5Ah. These are uncalibrated model assumptions, not an actual pack curve. The reported battery voltage is recomputed after the step. The model stops charging atSOC0.98 and pauses it during a pending source transfer; hardware instead obeys the real charger's CC/CV/NTC and local voltage-based inhibit supervisor. No input-voltage dynamics, control-loop stability, polarization, aging or thermal battery model is simulated.

Bus nominal12V when source active,0 during off/transfer. Three loads1/3/2W are constant-power idealisations, no detailed motor electrical model. Converter efficiency and budget constrain control; startup is handled as staging rather than an inductor/motor simulation. Source deadtime creates unserved energy. ENS=sum(6W-P_served)*dt/3600 Wh. Runtime=SOC*C*V*eta_battery/P_load when load>0; undefined with zero load. Loss field also includes unused/curtailed PV potential, so it is not converter calorimetric heat. Split this before any physical efficiency claim.

Measurement provenance: synthetic plant='simulated'; stored sample playback='replayed'; parsed devices='measured'. SOC, qualified solar capacity and runtime remain estimates even within hardware packets. Generated PV power is sum of valid measured panel powers; capacity bound is a different field/meaning. Missing hardware fields are absent or null; frontend em dashes distinguish missing from real zero. Host monotonic freshness is separate from MCU uptime; no UTC synchronisation is assumed. Simulation optional estimate errors compare against synthetic truth only; hardware model error requires calibrated reference measurements.

SQLite stores mode and JSON snapshots, plus separate command/fault events. Mode transitions reset volatile estimator/control state. Replay reads existing snapshots and has no command publication path. SQLite retains data until operator archives it; no automatic retention service is installed. Loopback HTTP/WebSocket is intended for one trusted local operator, no internet exposure/authentication promise.
